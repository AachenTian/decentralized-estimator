# Architecture

## 1. System state

There are three independent `OwnerLearner` instances. Owner `i` contains:

- live actor `pi_i`;
- Q1/Q2 and target Q1/Q2;
- entropy temperature `alpha_i`;
- five-member probabilistic joint dynamics ensemble `M_i`;
- private real replay `B_real_i`;
- private model replay `B_model_i`;
- private optimizer states;
- private RNG streams;
- private critic/dynamics normalization statistics.

A common immutable actor-observation normalizer is copied to all owners so that
an exchanged actor parameter snapshot has identical semantics everywhere.

## 2. Synchronization round

At the beginning of round `k`:

1. Deep-copy the three live actor parameter trees.
2. Build one immutable snapshot bank:
   `(pi_0^k, pi_1^k, pi_2^k)`.
3. Do not average parameters.
4. Do not overwrite any live actor.
5. Freeze the snapshot bank for the whole round.

## 3. Private real collection

Each owner has an independent environment collector.

- Owner 0 writes only to `B_real_0`.
- Owner 1 writes only to `B_real_1`.
- Owner 2 writes only to `B_real_2`.

Collection uses the frozen snapshot bank for all three agents. This makes the
round independent of owner execution order. Owners may share an environment
random-number schedule for common-random-number comparisons, but policy action
RNG streams remain distinct.

Each transition stores:

- model/global state, shape `(18,)`;
- actor observations, shape `(3, 18)`;
- joint policy action, shape `(3, 2)`;
- reward vector, shape `(3,)`;
- next model/global state, shape `(18,)`;
- next actor observations, shape `(3, 18)`;
- episode done;
- pair-collision diagnostics.

## 4. Private dynamics training

Each owner trains one independent ensemble with five members.

Input per member:

- normalized model/global state: 18;
- normalized joint action: 6;
- total input dimension: 24.

Output per member:

- mean and bounded log variance for the delta of all agent local states;
- output dimension: 12, ordered as three blocks of
  `[delta_px, delta_py, delta_vx, delta_vy]`.

Landmark positions are static and copied to the predicted next state.

Terminal/auto-reset transitions are excluded from dynamics loss.

Every ensemble member uses an independent bootstrap mask or independently
resampled minibatch.

## 5. Private model rollout

Owner `i` samples initial states only from `B_real_i`.

Actions:

- focal action: owner `i` actor snapshot at rollout-generation time;
- opponent actions: frozen actor snapshots from the round snapshot bank.

The joint dynamics ensemble predicts the next joint state. Synthetic rollout
stops on:

- configured horizon;
- predicted episode termination;
- predicted collision;
- excessive ensemble epistemic uncertainty.

There is no opponent model and no communication branch.

Synthetic transitions are written only to `B_model_i`.

## 6. Independent SAC updates

Each owner performs its own updates from its own replay buffers.

Critic input:

- state 18;
- joint action 6;
- total dimension 24.

For actor update of owner `i`:

- `a_i` is generated by the live actor and carries gradient;
- all `a_j`, `j != i`, are generated by frozen snapshots;
- opponent actions use stop-gradient;
- only actor `i` is updated.

The three live actors diverge during local updates. Their new parameters are
exchanged only at the next synchronization round.

## 7. Initial schedule

Per owner:

- 200 synchronization rounds;
- 300 real transitions per round (`12 envs x 25 steps`);
- 50 dynamics optimizer updates per round;
- 100 SAC update cycles per round;
- batch size 1024;
- five dynamics members;
- model rollout batch size 1024;
- horizon schedule from 1 to 6.

Totals per owner:

- 60,000 real training transitions;
- 10,000 ensemble optimizer updates;
- 20,000 SAC update cycles.

System total:

- 180,000 real training transitions;
- 30,000 ensemble optimizer updates;
- 60,000 SAC update cycles.

## 8. Non-negotiable invariants

1. No replay object is shared across owners.
2. No optimizer state is shared across owners.
3. No live actor is overwritten during snapshot exchange.
4. No actor averaging is performed.
5. Opponent actor snapshots are immutable within one round.
6. Opponent actions have zero gradient in focal actor loss.
7. Dynamics training excludes terminal auto-reset contamination.
8. Model rollout termination reasons are logged separately.
9. Environment interaction counts are tracked per owner and system-wide.
10. Checkpoints contain all three independent learners and the snapshot round.
